# セットアップ / Setup

## 日本語

v0.1.3 では AltServer が `127.0.0.1:27015` の公式 netmuxd に直接接続します。互換アダプターは配布・起動しません。旧構成から切り替える場合は、新バイナリ、netmuxd の待受ポート、systemd の依存関係、監視処理をまとめて変更し、旧アダプターを停止・無効化する必要があります。アダプターだけを停止しても移行は完了しません。異なるバージョンで準備した状態の再利用は拒否します。

新規導入は README の `--prepare`、`--configure` の順で行います。準備だけなら iPhone は不要です。設定時に既存の USB ペアリング情報を使用します。セットアップが Apple の認証情報を尋ねることはありません。

通常はホストの LAN IPv4、USB 接続された iPhone の UDID と Wi-Fi MAC を自動検出します。複数端末や複数 NIC がある場合は `ALTSERVER_HOST_IP`、`IPHONE_UDID`、`IPHONE_WIFI_MAC`、必要なら `IPHONE_FALLBACK_IP` をローカルの環境変数として指定できます。入力は形式を検証し、シェル用に引用して権限 0600 の `/etc/altserver-native.env` に保存します。Apple ID やパスワードは指定しません。

`sudo` が環境変数を消す場合は `sudo ALTSERVER_HOST_IP=... IPHONE_UDID=... IPHONE_WIFI_MAC=... sh install.sh --configure` のように直接渡してください。`...` は説明用で、実際の値に置き換えます。

## Anisette（v0.4.0 以降）

Anisette は、Windows 版 iCloud のライブラリを Docker 上の Wine で動かして生成します（`altserver-icloud-local.service`、`127.0.0.1:6972`）。Android 系の anisette-v3-server は Apple に拒否される（`-80045`）ため使用しません。コンテナイメージは準備時に `anisette/icloud-wine` からビルドし、イメージ ID で固定します。

Apple のライブラリは再配布できないため、利用者の Windows PC から取り込みます。Windows 版 AltServer と iCloud（32 ビット版 Apple Application Support を含む）が動作する PC で `scripts/windows/export-apple-runtime.ps1` を実行し、作成された `apple-runtime.tar.gz` を Debian にコピーして `sudo sh install.sh --import-apple-runtime apple-runtime.tar.gz` を実行します。`iCloud_main.dll` 261.7.0.49 と `CoreADI.dll` 4.17.0 を SHA-256 で検証し、Apple のルート証明書も公式 URL から取得してハッシュで検証します。取り込み先は `/opt/altserver-native/icloud-local/apple` です。Apple ID・トークン・端末の状態は含みません。

Wine の状態（Apple が信頼した端末情報）は `/var/lib/altserver-native/icloud-local` に保存します。このディレクトリを消したり作り直したりすると、Apple から新しい端末として扱われます。

### 2要素認証の入力欄が出ない場合

新しい端末として扱われている間は、AltStore のサインインがコード入力欄を出さずに `-22411` で失敗します。Apple が 2 要素認証を求める一方で、AltStore が対応する方式（`au`）を返さないためです（[AltStore#1737](https://github.com/altstoreio/AltStore/issues/1737)）。次の手順で一度だけ信頼させます。

1. iPhone の「設定 → 自分の名前 → サインインとセキュリティ → 2ファクタ認証 → 確認コードを受け取る」でコードを表示します（表示されない場合は、Wi-Fi とモバイル通信を一時的に切ると表示されることがあります）。
2. サーバーで `sudo altserver-apple-trust` を実行し、Apple ID・パスワード・コードを入力します。
3. `Success` と表示されたら AltStore で再度リフレッシュします。

パスワード・コード・Apple のトークンはメモリー上だけで扱い、表示・保存しません。表示するのは Apple の状態コードだけです。

### v0.3.x からの移行

`/etc/altserver-native.env`・`/etc/systemd/system`・ペアリング情報をバックアップしてから行ってください。新しい版の `install.sh --import-apple-runtime` で Apple のライブラリを取り込み、`scripts/install-helper-scripts.sh` と `scripts/install-systemd-units.sh` を実行する前に、環境ファイルの `ALTSERVER_ANISETTE_SERVER`・`ANISETTE_URL` を `http://127.0.0.1:6972` に変更し、`ICLOUD_ANISETTE_IMAGE`（`docker build` したイメージ ID）、`ICLOUD_ANISETTE_STATE_DIR`、`ICLOUD_ANISETTE_APPLE_DIR` を追加します。最後に `altserver-anisette-docker.service` を停止・無効化して削除し、上記の手順でサーバーを信頼させます。

既存環境からの自動移行はこのプレビューの対象外です（上記の手動移行を参照）。インストーラは既存設定やバイナリを検出すると停止します。稼働中の構成を削除して回避しないでください。旧環境の設定、ペアリング情報、Anisette 状態、systemd の追加設定をバックアップし、別の Debian ホストで動作確認してから切り替えてください。今回の作業では既存実機のサービスは置き換えていません。

停止は `sudo systemctl stop altserver-native-healthcheck.timer altserver-native-boot-recover.service altserver-native-healthcheck.service altserver-native.service iphone-mobdev-address.service iphone-mobdev-service.service altserver-native-netmuxd.service altserver-icloud-local.service` で行います。状態データは残ります。Docker や Avahi を共有する他のアプリには影響を与えません。再開は `sudo systemctl start altserver-native.service altserver-native-healthcheck.timer` で行います。サーバーの依存サービスも起動します。

## English

In v0.1.3, AltServer connects directly to official netmuxd at `127.0.0.1:27015`. The compatibility adapter is no longer distributed or started. Switching from the old setup requires coordinated changes to the binary, netmuxd listening port, systemd dependencies and health checks, plus stopping and disabling the old adapter. Stopping only the adapter does not complete migration. Setup rejects state prepared by a different version.

For a new installation, run `--prepare`, then `--configure` as shown in the README. Preparation needs no phone. Configuration uses an existing USB pairing record. Setup never asks for Apple credentials.

The host LAN IPv4 and the USB-connected phone's UDID and Wi-Fi MAC are normally detected automatically. For multiple devices or interfaces, set `ALTSERVER_HOST_IP`, `IPHONE_UDID`, `IPHONE_WIFI_MAC` and optionally `IPHONE_FALLBACK_IP` as local environment variables. Values are validated, shell-quoted and stored in `/etc/altserver-native.env` with mode 0600. Do not supply an Apple ID or password.

Pass variables directly to `sudo`, for example `sudo ALTSERVER_HOST_IP=... IPHONE_UDID=... IPHONE_WIFI_MAC=... sh install.sh --configure`, to avoid its environment reset. Replace the illustrative `...` placeholders with local values.

### Anisette (v0.4.0 and later)

Anisette is generated by Apple's Windows iCloud libraries running under Wine in Docker (`altserver-icloud-local.service`, `127.0.0.1:6972`). The Android-based anisette-v3-server is no longer used because Apple rejects it with `-80045`. Preparation builds the container image from `anisette/icloud-wine` and pins it by image ID.

Apple's libraries cannot be redistributed, so they are imported from the user's Windows PC. On a PC where AltServer for Windows and iCloud (including 32-bit Apple Application Support) work, run `scripts/windows/export-apple-runtime.ps1`, copy the resulting `apple-runtime.tar.gz` to the Debian host and run `sudo sh install.sh --import-apple-runtime apple-runtime.tar.gz`. Setup verifies `iCloud_main.dll` 261.7.0.49 and `CoreADI.dll` 4.17.0 by SHA-256, downloads Apple's root certificate from Apple's URL and verifies its hash, then installs everything to `/opt/altserver-native/icloud-local/apple`. No Apple ID, tokens or device state are included.

Wine state, the device identity Apple trusts, lives in `/var/lib/altserver-native/icloud-local`. Deleting or recreating it makes Apple treat the server as a new device.

#### When AltStore shows no two-factor code field

While the server is a new device to Apple, AltStore sign-in fails with `-22411` without showing a code field: Apple requires two-factor authentication but offers no method (`au`) that AltStore handles ([AltStore#1737](https://github.com/altstoreio/AltStore/issues/1737)). Establish trust once:

1. On the iPhone, open Settings > [your name] > Sign-In & Security > Two-Factor Authentication > Get Verification Code. If no code appears, temporarily turning off Wi-Fi and cellular data may help.
2. Run `sudo altserver-apple-trust` on the server and enter the Apple ID, password and code.
3. After `Success`, refresh again in AltStore.

The password, code and Apple tokens stay in memory and are never printed or stored; only Apple status codes are shown.

#### Migrating from v0.3.x

Back up `/etc/altserver-native.env`, `/etc/systemd/system` and pairing records first. Import Apple's libraries with the new `install.sh --import-apple-runtime`. Before running `scripts/install-helper-scripts.sh` and `scripts/install-systemd-units.sh`, change `ALTSERVER_ANISETTE_SERVER` and `ANISETTE_URL` in the environment file to `http://127.0.0.1:6972`, and add `ICLOUD_ANISETTE_IMAGE` (the ID of the image you built with `docker build`), `ICLOUD_ANISETTE_STATE_DIR` and `ICLOUD_ANISETTE_APPLE_DIR`. Finally stop, disable and remove `altserver-anisette-docker.service`, then establish trust as described above.

Automatic migration of an existing installation is outside this preview's scope (see the manual migration above). Setup stops if it finds existing configuration or binaries. Do not delete a working installation to bypass this check. Back up configuration, pairing records, Anisette state and systemd overrides, validate on a separate Debian host, then plan the switch. The existing physical server's services were not replaced during this work.

To stop, run `sudo systemctl stop altserver-native-healthcheck.timer altserver-native-boot-recover.service altserver-native-healthcheck.service altserver-native.service iphone-mobdev-address.service iphone-mobdev-service.service altserver-native-netmuxd.service altserver-icloud-local.service`. State is retained. Other applications sharing Docker or Avahi are unaffected. Resume with `sudo systemctl start altserver-native.service altserver-native-healthcheck.timer`; server dependencies also start.
