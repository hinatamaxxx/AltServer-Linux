# AltServer-Linux

[日本語](README.md) | English

> [!WARNING]
> **This repository is no longer maintained.** Since late October 2026, Apple-side changes have made free Apple ID signing fail with errors such as `-80046` and, with AltStore 2.3.1, `HTTP 503`. Keeping up became too much work, so the author switched to signing with a paid Apple Developer Program membership. There will be no further updates, bug fixes or support. The code and documentation remain for reference.

A complete setup for running AltServer on a Debian server at home, so the AltStore app on your iPhone can refresh apps over Wi-Fi. No Windows PC or Mac has to stay on.

This is an **unofficial preview** based on [NyaMisty/AltServer-Linux](https://github.com/NyaMisty/AltServer-Linux). It is not provided by the AltStore team.

## What it does

- Refresh apps from AltStore on your iPhone through AltServer on Debian
- Run AltServer, iPhone communication and Apple authentication data (Anisette) as systemd services, with automatic recovery
- Optionally check status and run recovery from a browser-based console

## Requirements

| Requirement | Purpose |
| --- | --- |
| Debian 12 or 13 (amd64, systemd) with internet access | The server that runs AltServer |
| One iPhone and a USB cable | Initial pairing ("Trust"). Later refreshes use Wi-Fi |
| A Windows PC where AltServer for Windows and iCloud work | Used once, to export Apple's iCloud libraries |
| The iPhone and the server on the same LAN | For Wi-Fi refresh, the iPhone finds and connects to the server on the LAN |

Other CPU architectures and Docker Desktop are not supported. Setup never asks for your Apple ID or password; you enter them when signing in to AltStore.

## Installation

### 1. Prepare the server

```sh
git clone https://github.com/hinatamaxxx/AltServer-Linux.git
cd AltServer-Linux
sudo sh install.sh --prepare
```

This installs the required packages, AltServer and netmuxd, and builds the Anisette container image. No iPhone is needed yet, and AltServer is not started. You can also extract `AltServer-Linux-amd64-setup.tar.gz` from the [releases](https://github.com/hinatamaxxx/AltServer-Linux/releases) and run the same command.

### 2. Import Apple's iCloud libraries

Apple authentication uses data generated by Apple's Windows iCloud libraries running under Wine. Apple's files cannot be redistributed, so they are not in this repository.

On the Windows PC, run `scripts\windows\export-apple-runtime.ps1` from this repository:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\export-apple-runtime.ps1
```

Copy the resulting `apple-runtime.tar.gz` to the server and import it:

```sh
sudo sh install.sh --import-apple-runtime apple-runtime.tar.gz
```

The import verifies the library versions by hash. The archive contains no Apple ID or password.

### 3. Connect the iPhone and activate

Connect exactly one iPhone by USB and choose "Trust" when the iPhone asks whether to trust this computer. Then activate:

```sh
sudo sh install.sh --configure
sudo /usr/local/sbin/altserver-native-healthcheck
```

If setup reports a missing pairing record, unlock the iPhone, run `idevicepair pair`, choose "Trust", and rerun `--configure`.

### 4. Sign in and refresh in AltStore

Disconnect the USB cable, join the same Wi-Fi network as the server, and refresh from AltStore.

On the first sign-in, AltStore may fail with `-22411` without showing a two-factor code field. Apple treats the server as a new device and asks for a verification method AltStore does not handle ([AltStore#1737](https://github.com/altstoreio/AltStore/issues/1737)). If that happens, make Apple trust the server once:

1. On the iPhone, open Settings > [your name] > Sign-In & Security > Two-Factor Authentication > Get Verification Code.
2. On the server, run `sudo altserver-apple-trust` and enter your Apple ID, password and the code.
3. After `Success`, refresh again in AltStore.

The password and code are never stored.

## Troubleshooting

| Symptom | What to do |
| --- | --- |
| `AltServer could not be found` (error 1200) | Turn the iPhone's Wi-Fi off and on, then refresh again. Also check that the iPhone and the server are on the same LAN |
| `-22411` with no code field | Run `altserver-apple-trust` as described in "4. Sign in and refresh in AltStore" |
| `-80045` (This action cannot be completed at this time) | Apple rejects the Android-based Anisette used through v0.3.x. Migrate to v0.4.0 ([migration](docs/setup.md)) |
| Checking service status | Run `sudo /usr/local/sbin/altserver-native-healthcheck`. `healthy` means OK; `waiting_for_device` is the normal state while the iPhone is away |

The health check runs 15 seconds after the previous check finishes. Services are restarted only after three consecutive failures, at least five minutes apart. `healthy` covers the server and protocol checks, not a successful app refresh. The health check never signs in to Apple or refreshes apps.

## Web console (optional)

Check service status, iPhone connectivity and diagnostic logs, and run recovery, from a Japanese/English browser console. Use Tailscale on both the server and the accessing PC; sign-in uses HTTPS and passkeys.

```sh
sudo sh scripts/install-web-ui.sh --tailscale
```

Run it after activating AltServer. LAN access without Tailscale and public internet exposure are not supported. See [web console](docs/web-ui.md).

## How it works

| Service | Role |
| --- | --- |
| `altserver-native.service` | AltServer itself. Announces itself on the LAN via Bonjour and handles AltStore requests |
| `altserver-native-netmuxd.service` | Communication with the iPhone over Wi-Fi (official netmuxd) |
| `altserver-icloud-local.service` | Docker container that generates Anisette by running Apple's Windows iCloud libraries under Wine |
| `iphone-mobdev-address.service` and related | Find the configured iPhone and register it with netmuxd |
| `altserver-native-healthcheck.timer` | Periodic checks and automatic recovery |

Configuration is stored in `/etc/altserver-native.env` (mode 0600). The device identity Apple trusts lives in `/var/lib/altserver-native/icloud-local`. Deleting that directory makes Apple treat the server as a new device, and `altserver-apple-trust` is needed again.

## Updating and migration

The installer stops without changing anything if it finds an existing installation. Migration from v0.3.x is manual; see [setup and migration](docs/setup.md).

## Notes

- This is a preview. Refresh has been confirmed on an existing Debian server with an iPhone on iOS 27. A complete clean installation, behavior after a host reboot and long-duration operation are unverified. See [verification](docs/verification.md).
- Never commit Apple credentials, pairing records, device identifiers, logs, Anisette or Wine state, or Apple's libraries.

## For developers

To build from source, run the commands below. Normal installation does not need the build environment.

```sh
git clone --recursive https://github.com/hinatamaxxx/AltServer-Linux.git
cd AltServer-Linux
docker build -f docker/Dockerfile.build --target export --output type=local,dest=dist .
```
